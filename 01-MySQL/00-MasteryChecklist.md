## 2. 索引底层为什么用 B+ 树？聚簇索引和二级索引的区别？

**锚点**：官方文档 / 《高性能 MySQL》第 5 章

- [ ] **及格**：说出 B+ 树特征——**叶子节点存数据、非叶子只存键、叶子之间有序相连**；聚簇索引（主键索引，叶子存整行）vs 二级索引（叶子存主键值，需要**回表**）
- [ ] **良好**：及格 + 能解释**为什么是 B+ 树**——磁盘 IO 次数由树高决定，B+ 树矮且宽（一次 IO 读更多键）、叶子有序支持**范围查询**；对比哈希（不支持范围）、红黑树（太高）、B 树（非叶子也存数据，页能存的键更少）
- [ ] **精通**：良好 + 能应对追问——**覆盖索引**（不回表）、**最左前缀原则**、**索引下推 ICP**、哪些写法会导致索引失效（函数/隐式转换/like 前导通配符/OR 连接非索引列）

## 3. 事务 ACID 怎么实现？redo / undo / binlog 各是什么？

**锚点**：官方文档 InnoDB 事务 / 《MySQL 技术内幕：InnoDB 存储引擎》

- [ ] **及格**：ACID 四性——原子性（要么全做要么全不做）、一致性、隔离性、持久性；能说出各自的实现载体：**原子性靠 undo log、持久性靠 redo log、隔离性靠锁 + MVCC、一致性是前三者的结果**
- [ ] **良好**：及格 + 能说出三种日志——**redo log**（物理日志，记录页的修改，**WAL 先写日志**，崩溃恢复用）、**undo log**（逻辑日志，回滚 + 生成 MVCC 版本链）、**binlog**（归档/主从复制用，是 server 层日志）以及 redo 与 binlog 的区别
- [ ] **精通**：良好 + 能应对追问——**redo 和 binlog 的两阶段提交**（防止两个日志不一致）、组提交（group commit）、redo log 为什么可以**循环写**（大小固定，checkpoint 推进）、崩溃恢复时怎么判断哪些页需要重放

## 4. MVCC 原理？

**锚点**：《MySQL 技术内幕》MVCC 章节 / 官方文档

- [ ] **及格**：MVCC = 多版本并发控制，读不加锁也能看到一致快照；**读已提交**每次语句生成新快照，**可重复读**事务开始生成快照
- [ ] **良好**：及格 + 能解释机制——**undo log 版本链**（每行有 trx_id + roll_pointer 串成历史版本）、**ReadView**（记录活跃事务列表，判断哪个版本可见）、**快照读 vs 当前读**（`select` 是快照读，`select for update`/`update`/`delete` 是当前读，走锁）
- [ ] **精通**：良好 + 能应对追问——**可重复读下幻读怎么解决**（MVCC 对快照读解决幻读；当前读靠**间隙锁/临键锁**）、MVCC 能不能完全消除幻读（不能，当前读场景仍有）、`READ COMMITTED` 为什么每次语句建 ReadView

## 6. 主从复制原理？

**锚点**：官方文档 Replication

- [ ] **及格**：复制基于 **binlog**；三个线程——主库 **dump 线程**（发 binlog）、从库 **IO 线程**（拉取并写 relay log）、**SQL 线程**（重放 relay log）
