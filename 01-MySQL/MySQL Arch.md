## MySQL架构与执行流程
MySQL整体架构->Server层vs存储引擎层->SQL执行流程->各组件详解->面试高频题
### MySQL整体架构
```
客户端（连接）
    │
    ▼
┌─────────────────────────────────────────┐
│              Server 层                   │
│  ┌──────────┐ ┌──────────┐ ┌───────────┐ │
│  │ 连接器    │ │ 分析器    │ │ 优化器    │ │
│  │(连接管理) │ │(词法/语法)│ │(执行计划)  │ │
│  └──────────┘ └──────────┘ └──────────┘ │
│  ┌──────────────────────────────────┐   │
│  │          执行器                   │   │
│  └──────────────────────────────────┘   │
│  ┌─────────┐ ┌─────────┐                │
│  │ 查询缓存 │ │ 内置函数 │                │
│  └─────────┘ └─────────┘                │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│           存储引擎层（插件式）             │
│  ┌─────────┐ ┌─────────┐ ┌──────────┐  │
│  │ InnoDB  │ │ MyISAM  │ │  Memory  │  │
│  └─────────┘ └─────────┘ └──────────┘  │
└─────────────────────────────────────────┘
    │
    ▼
            文件系统（磁盘）
```
两层职责

|层|职责|说明|
|---|---|---|
|**Server 层**|连接管理、SQL 解析、优化、执行|跨存储引擎通用|
|**存储引擎层**|数据存取、索引实现、事务、锁|插件式，可插拔|
存储引擎层的插件化设计
```
-- 查看支持的引擎
SHOW ENGINES;

-- 查看当前默认引擎
SHOW VARIABLES LIKE 'default_storage_engine';  -- InnoDB

-- 建表指定引擎
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(50)
) ENGINE=InnoDB;  -- 或 MyISAM、Memory
```
### 一条SQL的执行流程
```
查询语句（SELECT）
① 连接器：建立连接、校验身份权限
      │
      ▼
② 查询缓存：命中直接返回（8.0 已移除）
      │ 未命中
      ▼
③ 分析器：词法分析 → 语法分析 → 语法树
      │
      ▼
④ 优化器：选择索引、生成执行计划
      │
      ▼
⑤ 执行器：调用存储引擎接口，逐行取数据
      │
      ▼
⑥ 存储引擎：读取数据，返回结果
```
连接器
```
// 职责：
// ① 建立 TCP 连接
// ② 校验用户名密码
// ③ 校验权限（后续操作受此权限约束）

// 连接管理：
// 短连接：每次用完断开（频繁建立开销大）
// 长连接：保持连接（注意内存占用，空闲太久被断开）
// 参数：wait_timeout（默认 8 小时）

// 连接池（应用层）：HikariCP、Druid
// 减少 TCP 建立/销毁开销
```
查询缓存（8.0已移除）
```
-- 早期版本有查询缓存
-- 命中：直接返回结果（key = SQL 文本）
-- 问题：任何表更新都会失效缓存 → 命中率低
-- MySQL 8.0 直接移除了查询缓存

-- 现在都用应用层缓存（Redis）
```
分析器
```
// 职责：SQL 文本 → 语法树
// ① 词法分析：识别关键字（SELECT、FROM）、表名、字段
// ② 语法分析：检查语法是否正确

// 错误示例：
SELECT * FROM users WHERE;  -- 语法错误
// ERROR 1064: You have an error in your SQL syntax
```
优化器
```
// 职责：决定怎么执行最优
// ① 选择索引（哪个索引）
// ② 决定表的连接顺序（多表 join）
// ③ 是否用索引下推、覆盖索引

// 示例：
SELECT * FROM users WHERE age > 20 AND name = '张三';
// 优化器选择：age 索引？name 索引？全表扫？
// 通过统计信息（cardinality 基数）估算成本

// EXPLAIN 就是看优化器的决策结果
```
执行器
```
// 职责：按照执行计划执行，调用存储引擎
// ① 判断是否有权限（每张表）
// ② 调用存储引擎接口
// ③ 处理返回的行

// 示例：全表扫描执行流程
// ① 调用 InnoDB 取第一行 → 判断条件 → 满足则加入结果
// ② 调用 InnoDB 取下一行 → 重复
// ③ 直到取完，返回结果集
```
存储引擎
```
// 职责：真正读写磁盘数据
// InnoDB：事务、行锁、MVCC、崩溃恢复
// 通过 Buffer Pool 缓存数据页，减少磁盘 IO
```
### 更新语句的执行流程
```
UPDATE users SET name = '李四' WHERE id = 1;
```
与查询流程的差异
```
① 连接器（同查询）
② 分析器（同查询）
③ 优化器（同查询）
④ 执行器：找到 id=1 的行
      │
      ├── ① 读数据：从 Buffer Pool（内存）读
      ├── ② 修改数据：在内存中修改
      ├── ③ 写 undo log：记录旧值（回滚用）
      ├── ④ 写 redo log（Prepare 阶段）
      ├── ⑤ 写 binlog（逻辑日志）
      ├── ⑥ 提交事务：redo log（Commit 阶段）
      │
      ▼
     成功返回
```
### Serve层vs存储引擎层关键点
各组件归属

|功能|归属|
|---|---|
|连接管理|Server 层|
|权限校验|Server 层|
|SQL 解析|Server 层|
|优化器|Server 层|
|缓存|引擎层（Buffer Pool）|
|索引|引擎层（B+ 树）|
|事务|引擎层（InnoDB）|
|锁|引擎层|
|日志|引擎层（redo/undo）+ Server 层（binlog）|
### 面试高频

> **Q:** "一条 SQL 在 MySQL 里怎么执行的？" 
> **A:** "六步：① 连接器建立连接、校验身份权限；②（旧版本）查缓存；③ 分析器做词法语法分析；④ 优化器选择索引和执行计划；⑤ 执行器调用存储引擎逐行取数据；⑥ 存储引擎真正读写磁盘（通过 Buffer Pool）。更新语句还要额外写 undo log、redo log、binlog 保证事务和恢复。"

> **Q:** "Server 层和存储引擎层什么区别？" 
> **A:** "Server 层负责连接、解析、优化、执行，跨引擎通用；存储引擎层负责数据存取、索引、事务、锁，插件式可切换。binlog 在 Server 层，redo/undo log 在 InnoDB 引擎层。"
